# 代肝单据管理系统 · 网页端

本地优先的接单账本：无需注册、无业务服务器，业务数据与截图保存在当前浏览器的 IndexedDB，
通过 `.dgbk` 完整备份与安卓端交换资料。

## 运行

```sh
cd web
npm install
npm run dev        # http://localhost:5173（开发模式不注册 Service Worker）
npm run build      # 输出 dist/，可作为静态站点部署
npm run preview    # 预览生产构建
npm run typecheck
npm test           # Vitest：领域规则、备份编解码、业务命令、更新安全、启动冒烟
npm run test:e2e   # Playwright：应用流程 + 两构建 PWA 升级生命周期
```

`dist/` 使用相对路径与 hash 路由，可直接放在任意静态主机的子目录下。

## PWA：安装与更新

生产构建注册 Service Worker（`dist/sw.js`，构建期生成），支持「安装到桌面」与断网使用。
开发模式不注册 Service Worker，避免缓存开发资源。

### 构建身份

- 每次生产构建由 `vite-plugins/pwaBuildPlugin.ts` 扫描真实构建产物，计算确定性 `buildId`
  （产物内容哈希 + 版本号 + 可选标签 + `src/pwa/sw.js` 模板原文），写入 `dist/sw.js`、
  `dist/version.json` 与 `index.html` 的 `daigan-build` 等 meta 标签。**无需手工改版本号**：
  产物或 Service Worker 代码变化 → 构建身份变化 → 缓存命名空间变化。
- `sw.js`、`version.json` 与所有启动资源（含懒加载分块）进入该构建专属的预缓存清单；
  Service Worker 自身不预缓存。支持子目录部署，不绑定固定域名。
- 缓存清理只在本部署 scope 的命名空间（`daigan-pwa-<scope 哈希>-`）内进行，其他 scope 与其他应用的缓存
  不受影响；旧版 `daigan-shell-v1` 名称不含 scope，仅在条目全部属于当前 scope 时才清理，否则保留。

### 更新生命周期

1. 用户继续使用当前版本；检测到新部署（启动后、回到前台（节流）、或手动「检查更新」）时后台下载。
2. 新 worker 把全部必需资源**原子预缓存**：任一资源失败/非 2xx 即安装失败，
   只删除本次安装的候选缓存（上一构建已激活的缓存不受影响），旧版本可继续用（含离线）；
   不会把未准备好的更新当作「已就绪」。
3. 安装成功的更新停在 waiting，**不自动激活**。仅当新版本完整准备好后才弹出通知：
   「发现新版本 / 新版本已准备好，更新后即可使用。」
4. 用户选择「立即更新」或「稍后」：
   - **稍后**：本次会话不再为同一构建反复弹窗；当前版本继续使用；可随时在
     「资料与设置 → 版本与更新」里「立即更新」。之后的不同构建仍会再次提示。
   - **立即更新**：先做安全检查（见下），通过后向 waiting worker 发显式激活消息，
     等待 controller 交接后**刷新一次**进入新版本。进行中按钮显示「更新中…」并防止重复触发；
     激活失败/超时会提示「更新未完成，请重试。」并恢复可重试状态，不丢数据、不谎报成功。
5. 页面设置中展示当前版本（`v版本 · buildId · 可选标签`）、更新状态与手动「检查更新」。
   手动检查严格区分：`当前已是最新版本` / `当前离线，无法检查更新` / `检查更新失败，请稍后重试`；
   检查未成功绝不回报「已是最新」。

### 更新安全（未保存编辑 / 进行中操作 / 多标签页）

- 应用内共享登记表（`src/pwa/updateSafety.ts`）跟踪「未保存编辑」（创建/编辑表单弹窗打开期间）
  与「进行中操作」（截图上传、备份导出/校验/恢复、模板导入导出、各类数据库写入）。
- 选「立即更新」时若有未保存编辑：提示 `请先保存或取消当前编辑，再更新。`，输入不会丢失；
  若有进行中操作：提示 `正在处理资料，请完成后再更新。`。处理完成后需用户再次点击更新，
  不会安排意外的自动刷新。干净空闲页面不受限制。
- 多标签页采用保守策略：**同 scope 的其他本应用页面打开时不允许激活**，
  提示 `请先关闭其他打开的本应用页面，再更新。`，关闭后重试即可。其他标签页不会被强制刷新。
- 无法确认其他标签页状态（查询超时、通信错误、响应非法）时**一律阻止激活**，提示
  `暂时无法确认其他页面状态，请稍后重试。`；本地阻塞项在异步查询返回后、激活前重新校验，
  且目标 waiting worker 被替换时中止本次更新。任一步失败都会复位为可重试状态。
  已知局限：关闭其他页面后到点击更新之间极短窗口内新打开的标签页无法感知；
  极端情况下其他页面已被切换 controller 时仅提示手动刷新，不强制重载。

### 本地数据

- 更新只替换页面资源。**IndexedDB 业务资料、截图附件与偏好不会被更新清空或重置**；
  更新流程不使用 `Clear-Site-Data`，不触碰业务数据库名与版本。
- 资料只存在于当前浏览器（含 IndexedDB 与 localStorage 偏好）。换域名、换浏览器或清理站点数据
  都会得到另一份本地资料；**定期在「资料与设置」导出 `.dgbk` 完整备份仍是必须的**。

### 为什么应固定使用稳定的生产域名

Service Worker 的缓存与安装状态按「源 + 路径」隔离。经常更换域名或子目录会让每处部署各自拥有一份
本地资料与缓存，离线入口与更新提示也会各自独立。请固定一个生产子域名单独部署本应用。

## 部署（Vercel）

以 `web` 为项目根目录（Root Directory: `web`）：

| 项 | 值 |
|---|---|
| Root Directory | `web` |
| Build Command | `npm run build` |
| Output Directory | `dist` |

缓存规则见 `web/vercel.json`（部署时随构建产物一起生效）：

- `/sw.js`、`/version.json`、`/index.html`、`/`：`public, max-age=0, must-revalidate`
  —— Service Worker 与更新元数据可及时再验证，避免长期缓存导致收不到更新；
- `/assets/*`（内容哈希）：`public, max-age=31536000, immutable`。

规则互不重叠以避免优先级歧义。hash 路由无需 SPA 重写，不要添加 catch-all rewrite。
本仓库不在本任务中执行部署或改 DNS；**生产环境响应头请以线上实测为准**（本地 e2e 服务器按同规则镜像验证）。

## 测试两构建升级

`npm run test:e2e` 会启动两个服务器：

1. `vite preview`（端口 `E2E_PORT`，默认 4317）：现有应用流程用例（`tests/e2e/app.spec.ts`）；
2. 升级服务器（端口 `E2E_UPGRADE_PORT`，默认 4318）：`tests/e2e/build-upgrade-fixtures.mjs`
   先构建 A/B 两份可区分的生产产物（`DAIGAN_BUILD_LABEL=A|B` 写入构建身份），
   `tests/e2e/upgrade-server.mjs` 在同一 origin 上按需切换发布、并可注入指定资源下载失败。

`tests/e2e/upgrade.spec.ts` 覆盖：首次安装不误报、A 断网可用、发布 B 后仅就绪才提示、「稍后」保持旧版、
接受更新仅刷新一次、未保存表单/进行中操作/其他标签页阻止更新、B 资源下载失败时 A 仍可用（含离线）、
更新后 B 断网可用且业务资料/截图/偏好保留、缓存清理不伤无关缓存、手动检查区分离线与失败。
版本判定以 `meta[name=daigan-build]` 与 `/version.json` 为准，不以刷新本身当作升级成功。

## 与安卓反馈的对应

网页版已采纳可在现有 schema 内实现的反馈（详见 `docs/handoffs/web-local-first.md`）：

- UF-001/UF-002：订单改日期、空单删除、已有记录只能作废。
- UF-003：已归档账号默认折叠，仍可展开、恢复。
- UF-004：重复周期支持每月固定日号，缺日跳过。
- UF-007/UF-009：账号与已作废订单支持级联删除，确认框展示影响范围。
- UF-011/UF-012/UF-013：订单改名、改价、与收款更正（保留原流水）。
- UF-016：设置中可关闭页面动效。

## 数据与安全

- 资料保存在 IndexedDB：业务库 `daigan-data-<uuid>`，协调状态在 `daigan-control`。
- 恢复会新建候选数据库并校验，确认后由控制库的单一事务切换活动指针；旧库随后删除。
  指针指向缺失/不完整数据库时应用报错并保留现场，不会自动新建空账本覆盖。
- 所有写入经 `navigator.locks` 的同源排他锁串行；不支持 Web Locks 的浏览器会提示。
- 每次操作携带打开表单时的资料代次，资料切换后旧页面写入会被 `STALE_DATASET` 拒绝。
- 本地数据库**不加密**；备份密码只保护导出的文件。

## 备份兼容

- 读取：多 schema 版本，普通 ZIP 或 `DAIGANBK` 加密信封（PBKDF2-HMAC-SHA256 210000 次、
  16 字节盐、12 字节 nonce、AES-256-GCM 128 位标签）。
- 写出：格式 v1、当前 schema、全部业务表、附件原始字节；网页扩展列仅非空导出以保旧端可读。
- 限额：归档 512 MiB、JSON 64 MiB、清单 1 MiB、5000 条目、2000 附件、单图 32 MiB、
  附件合计 384 MiB；解压超过 8 MiB 后压缩比上限 200。
- 业务校验覆盖外键、唯一键、枚举、金额区间、收款期次归属、截图双归属与提醒设置。
